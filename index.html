02 About

Two disciplines, one obsession: clarity

I started in spreadsheets and ended up in both a Jupyter kernel and a code editor. The through-line is the same question — how do you make something complicated look obvious?

On the data side I work in Python and SQL: cleaning, feature engineering, gradient boosting, forecasting, and the unglamorous validation that decides whether a model is allowed near a decision. On the web side I write HTML, CSS and JavaScript by hand — semantic markup, container queries, real focus states.

I care about the handoff. A model nobody trusts is a spreadsheet with extra steps, and a dashboard nobody can read is a screenshot. So I build the whole path: the pipeline, the evaluation, the interface, and the note that explains what it does not do.

  • Explain the model, not just the score. SHAP values, calibration curves and an honest limitations section.
  • Ship the interface too. If the output needs a translator, it is not finished.
  • Accessible by default. Keyboard paths, AA contrast and reduced-motion support from the first commit.
